# 브라우저 e2e

「사람 확인」으로 남던 화면·터미널·에이전트 흐름을 시험으로 고정한다(#168). 공장 Verify 가 PR 본문 `사람 확인`에 적힌 것만으로 충족으로 쳤고, 그 확인을 실제로 하는 단계가 없었다. 그 사이 #126(터미널 Ctrl+V)·#124(준비 표시)·#125(root 의 claude)가 대장 e2e 에서야 드러났다.

## 돌리기

```sh
scripts/ci.sh e2e                 # 스택 기동 → web/e2e/*.spec.ts → 정리(컨테이너·볼륨)
scripts/ci.sh e2e -g 붙여넣기      # 뒤 인자는 playwright test 로
bash scripts/check_workstation_image.sh --build   # workstation 이미지 실행 시험(#125)
```

- 스택: `docker/compose.dev.yaml` + `docker/compose.e2e.yaml`, 프로젝트 `infralab-e2e`. 호스트에는 web(그때 빈 포트)과 에이전트(7777)만 연다. 로그인은 dev-login, 강사는 `set_instructor`.
- 학생 PC 쪽: 실제 에이전트(`docker/agent.e2e.Dockerfile` — 운영과 같은 바이너리, kind·kubectl 없음)와 bash 만 든 작은 workstation. 에이전트 주소는 서버가 정한 `127.0.0.1:7777` 이라 그 포트가 비어 있어야 한다. 토큰은 사용자마다 달라 시험이 토큰을 안 뒤 에이전트를 다시 띄운다(`web/e2e/stack.ts`). agent 컨테이너는 스택과 함께 한 번만 만들고 그 안의 프로세스만 `docker/agent-e2e/agentctl` 로 바꾼다 — 시험 중 컨테이너를 다시 만들면 호스트에 veth 가 생기고 Chromium 이 진행 중인 요청을 `net::ERR_NETWORK_CHANGED` 로 끊는다(#227). 내린 상태(`stopAgent`)에서도 7777 은 열린 채 연결을 끊는다. workstation 도 같다 — 새 기수 폴더(`freshWorkDir`)는 컨테이너를 다시 만들지 않고 그 안에서 `/work` 를 비우고 돌던 프로세스를 끝낸다(#232). `web/e2e/stack.ts` 의 compose 손잡이는 `exec` 만 부를 수 있다.
- 연습 시나리오도 이 e2e 시나리오다(연습 묶음은 서버의 모든 시나리오를 연다). 공통 조작 `newStudent`·`startPractice`·`joinClassCohort` 는 `web/e2e/flows.ts` 에 있다.
- 시나리오는 `web/e2e/fixtures/scenarios/` 의 둘: `e2e-prepare`(준비가 `/work/app/ready.txt` 를 만들고, 검사 하나)와 `e2e-untouched`(「제출 없는 시나리오」 행을 보이려고 둔 것 — 시험이 제출하지 않는다).
- 연습 피드백은 공급사 키 없는 스택의 가짜 채점기(결정적)가 매긴다. AI 대화는 학생이 AI 도구로 남긴 세션 기록을 workstation 홈(`/root/.claude/projects/…jsonl`)에 심어(`plantClaudeSession`) 「AI 대화 함께 제출」로 올린다 — 진짜 AI 없이. 에이전트는 준비 표시보다 나중에 바뀐 파일만 읽으므로(초 단위) 환경 준비 뒤에 심는다.
- AI 프록시: e2e 스택은 `proxy`(`proxy/`)를 가짜 공급사 모드(`INFRALAB_PROXY_FAKE_PROVIDER=1`)로 올린다 — 진짜 키·외부 네트워크 없이 결정적 대답 `infralab fake provider reply.` 를 준다. backend 는 e2e 전용 공유 비밀로 이 프록시를 부르고(공급사 키가 「있음」으로 알려져 회차 설정에서 Claude Code·Codex 를 고른다), 지원자에게 주는 공개 주소도 compose 안 주소 `http://proxy:58090` 이다(workstation 이 같은 compose 망). 개발·운영 compose 에는 가짜 공급사 모드가 없다.
- 숨은 검사: backend 는 `INFRALAB_PROBLEMS_DIR=/e2e-problems`(`web/e2e/fixtures/problems`, 견본 문제은행)를 읽고 e2e 시나리오에 검사 하나가 붙는다. `problems-sample/` 에 두지 않은 까닭: 그 폴더의 모든 `<id>` 는 저장소 `scenarios/` 에 있어야 하는데(backend 시험이 그렇게 읽는다) e2e 시나리오는 저장소 시나리오가 아니다. 실제 문제은행 내용은 넣지 않는다.
- headless Chromium 은 다른 탭을 앞으로 가져와도(`bringToFront`) 문서를 숨기지 않는다 — 탭 이탈은 새로 고침(문서가 내려가며 숨겨짐)으로 낸다(#223).
- 재시도 없음, workers 1. 실패하면 `web/test-results/` 에 trace 가 남는다(CI 는 아티팩트 `e2e-traces`).

## 어디서 도는가

| 자리 | 무엇 | 까닭 |
|---|---|---|
| PR 검사 `ci.yml` 잡 `e2e`(필수) | `scripts/ci.sh e2e` | 버그를 병합 전에 잡는다. 공장 PR 도 GitHub App 토큰으로 만들어 ci.yml 이 돈다. `scripts/ci.sh all` 에는 넣지 않는다(docker·7777 포트). |
| 같은 잡, `docker/workstation/` 을 바꾼 PR 만 | `check_workstation_image.sh --build` | workstation 빌드가 몇 분 걸린다 — 바뀔 때만. |
| main `image.yml` workstation 빌드 뒤 | `check_workstation_image.sh <올린 이미지>` | 아키텍처마다 실제 이미지로. 실패하면 manifest·승격으로 가지 않는다. |

release 뒤 스모크로 두지 않은 까닭: 목적이 병합 전에 잡는 것이고, 운영(oracle)에는 쓰지 않는다.
